## 1. PRE-FLIGHT (запуск созвона за 30 сек)

### Что это

Экран, который появляется перед началом созвона. За 30 секунд пользователь задаёт тему, цель, подключает папки и нажимает «Начать».

### UX-сценарий

```
1. Пользователь запускает Куистант
2. Pre-flight экран появляется
3. Вводит тему: "Собес в Google Berlin, L4 Senior SWE"
4. Вводит цель: "Получить оффер $130k+"
5. Ставит галочки на папках:
   ✓ System Design Primer
   ✓ LeetCode Hard
   ✓ Behavioral Questions
6. [v2] Включает toggle "Ассистент без собеседника" если не собеседование
7. Нажимает "Начать →"
8. Открывается главное окно с пустыми плавающими окнами
```

### Данные

```sql
-- В app_state.db — реплики пишутся просто в `messages` (v3: без slices)
INSERT INTO messages (speaker, source, text) VALUES ('system', 'audio', 'Контекст: Собес в Google Berlin, L4 Senior SWE. Цель: получить оффер $130k+.');
```

### v2: Solo-режим

Если toggle включён — AudioCore получает `solo_mode=True`, микрофон выключен, захватывается только системный звук.

### Обоснование

Без Pre-flight ИИ не знает, что обсуждается → выдаёт общие подсказки. С контекстом — точные, тактические.

## 2. ПЛАВАЮЩИЕ ОКНА (конструктор виджетов)

### Что это

Независимые frameless-окна, которые пользователь может плодить сколько угодно. Каждое окно — отдельный чат с ИИ, со своими настройками.

### UX-сценарий

```
1. Пользователь в главном окне нажимает "+ Новое плавающее окно"
2. Появляется новое frameless-окно в случайном месте экрана
3. Пользователь перетаскивает его drag-handle'ом
4. Называет его "Coding Helper" (в header)
5. Выбирает модель: "Тяжелый мозг" (Claude Sonnet)
6. Привязывает папку "LeetCode Hard"
7. Пишет системный промпт: "Ты — эксперт по LeetCode Hard. Отвечай кратко, на Python."
8. Сохраняет пресет (крестик в header → "Сохранить пресет")
9. При следующем запуске это окно восстанавливается автоматически
```

### Данные

```sql
-- В app_state.db (таблица windows_config)
INSERT INTO windows_config (name, x, y, width, height, system_prompt, model, linked_folders)
VALUES ('Coding Helper', 100, 200, 400, 600,
```

Несколько плавающих окон = параллельные роли ИИ. "Coding Helper" + "Behavioral Coach" + "Salary Negotiator" — три разных эксперта в одном звонке.

## 3. ЗАХВАТ АУДИО (микрофон + системный звук)

### Что это

Захват двух аудио-потоков одновременно:

- **Микрофон** (твой голос)
- **Системный звук через WASAPI loopback** (голос собеседника через Zoom/Teams)

### Техническая реализация

```python
# Из форка Ecoute (AudioRecorder.py)
recorder = AudioRecorder(
    chunk_seconds=3,
    queue=audio_queue,
    capture_microphone=True,
    capture_system=True,
)
```

### UX-сценарий

```
1. Пользователь запускает Куистант и начинает созвон
2. Открывает Zoom, начинает звонок
3. Через 3 секунды Куистант начинает захватывать оба потока
4. Каждые 3 секунды — новый чанк в audio_queue
5. Поток транскрипции обрабатывает чанки параллельно
6. Реплики появляются в UI в реальном времени
```

### Обоснование

Без захвата аудио нет реплик → нет подсказок. Это фундамент.

### v2: Solo-режим

```python
recorder = AudioRecorder(
    chunk_seconds=3,
    queue=audio_queue,
    capture_microphone=False,  # ← выключено в solo-режиме
    capture_system=True,
)
```

## 6. 🆕 ПЕРЕМОТКА РЕПЛИК С АВТО-ОБНОВЛЕНИЕМ ОКОН (v3 — заменило слайсы)

### Что это

Клик на любую реплику в ленте → каждое плавающее окно (кроме замороженных) подтягивает свои N реплик до неё и обновляет свой контекст.

### Почему убрали слайсы

- Слайсы были «нарезкой диалога» — кнопка «Новый слайс», который создавал смысловую границу
- На практике создавали больше путаницы, чем пользы: пользователь забывал нажать «Новый слайс», ИИ путал контекст между темами
- Перемотка проще: ты просто кликаешь на интересную реплику, и каждое окно само подтягивает нужное количество

### UX-сценарий

```
1. Собеседник: "Расскажите про event-driven архитектуру"
2. В ленте появилась реплика speaker="other" с id=42
3. Ты хочешь, чтобы окно "System Design Expert" ответило именно про этот момент
4. **Кликаешь** на реплику в ленте
5. Окно "System Design Expert" подтягивает 10 реплик до id=42 (включая её) и обновляет свой контекст
6. Окно "Behavioral Coach" у тебя в freeze — оно не реагирует, продолжает работать со своим последним контекстом
7. В окне "Coding Helper" у тебя N=3, оно подтянуло только 3 последние реплики
```

### Настройки каждого окна

- `context_size` (по умолчанию 10, ползунок 1–50 в header окна) — сколько реплик тянуть ДО выбранной (включая её)
- `freeze` (по умолчанию False, toggle «❄️ Не переписывать» в header окна) — реагировать ли на клики

### Данные

```sql
-- v3: в windows_config добавлены 2 колонки
ALTER TABLE windows_config ADD COLUMN context_size INTEGER DEFAULT 10;
ALTER TABLE windows_config ADD COLUMN freeze INTEGER DEFAULT 0;

-- Сообщения — плоский список, без slices
CREATE TABLE messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    speaker TEXT NOT NULL,
    source TEXT DEFAULT 'audio',  -- 'audio' | 'keyboard' (v2)
    text TEXT NOT NULL,
    audio_path TEXT,
    screenshot_id INTEGER REFERENCES screenshots(id),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Логика обновления контекста окна

```python
# quistant_app/database.py (v3)
def get_messages_before(message_id: int, limit: int) -> list[dict]:
    """
    Возвращает последние `limit` реплик с id <= message_id,
    в хронологическом порядке (от старых к новым).
    Используется при клике по реплике в chat_lane.
    """
    with get_app_state() as conn:
        rows = conn.execute(
            """
            SELECT * FROM messages
            WHERE id <= ?
            ORDER BY id DESC
            LIMIT ?
            """,
            (message_id, limit),
        ).fetchall()
    return list(reversed(rows))


# Клик по реплике → обновление контекста всех окон
def on_message_click(message_id: int):
    """Публикуем событие — все FloatingWindow его услышат."""
    page.pubsub.send_others_on_topic(
        "replica_clicked",
        {"message_id": message_id},
    )

# В каждом плавающем окне:
def _on_replica_clicked(self, topic, message):
    if self.config["freeze"]:
        return  # заморожено — игнорируем

    message_id = message["message_id"]
    self.current_messages = get_messages_before(
        message_id=message_id,
        limit=self.config["context_size"],
    )
    self._refresh_chat_lane()

    if self.config.get("auto_query_on_click", True):
        self.trigger_llm_response()
```

### Обоснование

- **Простота:** убрали абстракцию «слайс», теперь есть просто «реплика» и «контекст»
- **Гибкость:** у каждого окна свой `context_size` — одно окно может смотреть на 3 последние реплики, другое на 20
- **Заморозка:** окна с `freeze=True` не реагируют на клики — это бывшая «заморозка» из v1, теперь работает на уровне окна, а не слайса
- **Без SQL-перепривязок:** при удалении реплик не нужно пересчитывать `slice_id`, нет cascade-логики

### Что НЕ делаем (что было в v1)

- ❌ Нет кнопки «Новый слайс»
- ❌ Нет таблицы `slices`
- ❌ Нет `messages.slice_id`
- ❌ Нет панели слайсов слева
- ❌ Нет перепривязки сообщений при удалении слайса

## 7. СКРИНШОТЫ ПО РАМКЕ (Smart Region Capture)

### Что это

Один раз выделяешь область экрана (где видно экран собеседника) → жмёшь `Ctrl+Shift+S` → снимок падает в активное плавающее окно → ИИ через 2 секунды даёт ответ.

### UX-сценарий

```
1. Перед созвоном: жмёшь "Выделить рамку" → экран темнеет → выделяешь область
2. Полупрозрачная рамка остаётся поверх всех окон
3. На созвоне собеседник показывает код в IDE
4. Жмёшь Ctrl+Shift+S
5. Через 100ms снимок появляется в активном окне "Coding Helper"
6. Через 2 секунды ИИ даёт разбор:
   "Это QuickSort. Сложность O(n log n). На этом собесе стоит упомянуть..."
```

### Технические детали

- Захват через `mss` (быстрая альтернатива PIL.ImageGrab)
- Сохранение в PNG в `data/screenshots/slice_<id>_<timestamp>.png`
- Запись в БД: `INSERT INTO screenshots (slice_id, file_path) VALUES (?, ?);`
- Embed в LLM-запрос как `image_url` (для vision-моделей)

### Обоснование

Собеседник показывает код/таблицу/график → тебе нужна помощь прямо сейчас. Не успел скопировать — упустил момент.

## 8. СКРЫТНОСТЬ ОТ ЗАХВАТА ЭКРАНА (WDA)

### Что это

Флаг `WDA_EXCLUDEFROMCAPTURE` делает окно невидимым при захвате экрана (Zoom, Teams, Meet).

### Технические детали

```python
import ctypes

WDA_EXCLUDEFROMCAPTURE = 0x00000011

def set_window_exclude_from_capture(hwnd: int):
    ctypes.windll.user32.SetWindowDisplayAffinity(hwnd, WDA_EXCLUDEFROMCAPTURE)
```

### UX-сценарий

```
1. Создаёшь 3 плавающих окна (Coding + Behavioral + Salary)
2. Запускаешь Zoom, включаешь демонстрацию экрана
3. Ты видишь: Zoom + свои 3 окна + рамку
4. Собеседник видит: только твой рабочий стол БЕЗ окон Куистанта и рамки
5. Никаких следов на записи звонка
```

### Обоснование

Без скрытности собеседник увидит → будет думать, что ты мошенничаешь → продукт мёртв.

## 9. АВТОРИЗАЦИЯ ЧЕРЕЗ САЙТ (Device Flow)

### Что это

Программа требует авторизации. Открывает браузер → пользователь логинится на сайте → подтверждает доступ → JWT сохраняется в программе.

### UX-сценарий

```
1. Запускаешь Куистант → окно "Войти в аккаунт"
2. Нажимаешь "Войти" → открывается браузер на https://quistant.com/connect?code=482917
3. На сайте вводишь email, получаешь magic link, логинишься
4. Видишь "Куистант запрашивает доступ" → нажимаешь "Разрешить"
5. Программа получает JWT → сохраняет в app_state.db.auth
6. Следующие запуски — автоматический вход
```

### Данные

```sql
-- В app_state.db
UPDATE auth SET jwt_token = ?, hwid = ?, last_check = NOW() WHERE id = 1;

-- В server.db (device_auth)
INSERT INTO device_auth (device_code, status) VALUES ('482917', 'pending');
-- После подтверждения:
UPDATE device_auth SET status = 'authorized', user_id = ?, jwt_token = ? WHERE device_code = '482917';
```

### Обоснование

Без авторизации нет лицензий → нет монетизации.

## 11. ИНТЕГРАЦИЯ С LLM

### Что это

Куистант отправляет в LLM:

1. Системный промпт (роль)
2. История реплик (последние N реплик из контекста окна, по умолчанию 10)
3. Топ-5 RAG-чанков
4. Скриншот (если есть)
6. Получает стриминговый ответ

### Поддерживаемые провайдеры

- **OpenAI**: GPT-4o, GPT-4o-mini, o1-preview
- **Anthropic**: Claude 3.5 Sonnet, Claude 3.5 Haiku
- **OpenRouter**: 100+ моделей через единый API
- **Ollama / LM Studio** (локально)

### UX-сценарий

```
1. Интервьюер: "Расскажите про event-driven architecture"
2. Через 1 секунду в плавающем окне появляется ответ:
   "Упомяни Kafka + RabbitMQ..."
   "Eventual consistency..."
   "Пример с e-commerce: order created → payment processed → email sent..."
3. Ты говоришь это своими словами → звучишь подготовленным
```

## 12. MARKDOWN-RAG (ЭМБЕДДИНГИ)

### Что это

Подключаешь папки с Markdown (резюме, заметки, документация) → Куистант индексирует → при каждом запросе к ИИ находит топ-5 релевантных чанков → подставляет в контекст.

### UX-сценарий

```
1. Pre-flight → "Подключить папку" → выбираешь ~/Documents/System-Design-Primer
2. Куистант индексирует все .md файлы (прогресс-бар)
3. На созвоне интервьюер спрашивает про CDN
4. Куистант: "Найдено в System-Design-Primer/04-cdn.md:
   - CloudFront, Fastly, Akamai
   - Pull vs Push CDN
   - Cache hit ratio"
5. LLM использует это для ответа
```

### Движки эмбеддингов

- **OpenAI** (`text-embedding-3-small`) — платный, быстрый
- **BGE-m3** (локально) — бесплатный, требует GPU для скорости
- **all-MiniLM-L6-v2** (локально) — лёгкий fallback

### Данные

```sql
-- knowledge_base.db
CREATE TABLE chunks (
    id INTEGER PRIMARY KEY,
    folder_id INTEGER,
    file_path TEXT,
    chunk_index INTEGER,
    text TEXT,
    embedding BLOB,  -- numpy array tobytes()
    token_count INTEGER
);
```

## 🆕 13. АССИСТЕНТ БЕЗ СОБЕСЕДНИКА (v2)

### Что это

Режим «solo» — Куистант слушает только системный звук (без микрофона). Применимо для YouTube, подкастов, лекций, фильмов.

### UX-сценарий

```
1. Pre-flight → включить toggle "Ассистент без собеседника"
2. Открыть YouTube с лекцией 3Blue1Brown про латентное пространство
3. Куистант слушает + распознаёт
4. Студент печатает с клавиатуры: "Что такое латентное пространство?"
5. Куистант отвечает: "В этом видео (таймкод 12:34) лектор объясняет..."
```

### Технические детали

```python
class AudioCore:
    def __init__(self, slice_id: int, solo_mode: bool = False):
        self.solo_mode = solo_mode

    def start(self):
        recorder = AudioRecorder(
            capture_microphone=not self.solo_mode,  # ← ключевая строка
            capture_system=True,
        )
```

### Обоснование

- Удваивает TAM (студенты, ютуберы, изучающие языки, преподаватели)
- Не требует скрытности (никто не видит твой экран дома)
- Тот же код, что для live-режима — только флаг

## 🆕 14. ТЕКСТ С КЛАВИАТУРЫ = РЕПЛИКА (v2)

### Что это

Пользователь набирает текст в плавающем окне → он добавляется как `speaker="user"`, `source="keyboard"` → ИИ отвечает как на голосовую реплику.

### UX-сценарий

```
1. На созвоне собеседник задал сложный вопрос
2. Ты не хочешь говорить вслух (например, в открытом офисе)
3. Быстро набираешь ответ в плавающем окне
4. Куистант показывает тебе, как это лучше сформулировать
5. Ты говоришь улучшенную версию
```

### Данные

```sql
INSERT INTO messages (slice_id, speaker, source, text) 
VALUES (1, 'user', 'keyboard', 'Расскажи про опыт с Kafka');

-- source='audio' | 'keyboard' | 'system'
```

### Обоснование

- Тихая обстановка (библиотека, офис)
- Сурдоперевод (глухие/глухонемые пользователи)
- Чёткость формулировки
- Solo-режим (когда микрофон выключен)

## 15. BYOK (СВОЙ КЛЮЧ ОТ LLM)

### Что это

Пользователь вставляет свой OpenAI / Anthropic API-ключ в настройках. Куистант использует его. Тариф «Your Key» — 500 ₽/мес за оболочку.

### Где хранится ключ

- **Windows Credential Manager** (не в БД в открытом виде)
- Зашифрован через `keyring` библиотеку

### Почему BYOK

- 100% маржа для нас (только стоимость оболочки)
- Для пользователя: дешевле на 90%, если у него уже есть ключ
- Приватность: данные не проходят через наш сервер (только LLM-провайдеру)

## 16. ДИНАМИЧЕСКАЯ СМЕНА КОНТЕКСТА «НА ЛЕТУ»

### Что это

Пользователь может изменить тему и цель в любой момент — голосом или текстом.

### UX-сценарий

```
На созвоне перешли от System Design к зарплате.
[Голосом]: "Эй, Куистант, запомни — теперь обсуждаем зарплату"
[Или текстом]: в header плавающего окна меняет поле "Контекст"

Следующие ответы ИИ учитывают новый контекст, не старый.
```

## 🆕 17. ГОЛОСОВАЯ АКТИВАЦИЯ КОНТЕКСТА (v2)

### Что это

Wake-word «Эй, Куистант» + голосовая команда для смены контекста.

### Технические детали

- **Wake-word:** Picovoice Porcupine (~$5/мес) или open-source Snowboy
- **Распознавание команды:** Whisper на следующих 5 секундах аудио
- **Парсинг команды:** «запомни — теперь [тема]»

### UX-сценарий

```
1. Включена голосовая активация
2. На созвоне перешли к зарплате
3. Говоришь: "Эй, Куистант, запомни — теперь обсуждаем зарплату"
4. Через 2 секунды в header: "Контекст: зарплата"
5. Следующие ответы ИИ — про зарплату
```
